>         q = Queue(NUM_VERTICES)
>         # define v, w as vertex
>         for each vertex v:
>             if v.indegree == 0:
>                 q.enqueue(v)

>             v = q.items[0]
>             q.dequeue()

>                 if w.indegree == 0:

> **Source:** [เปิด PDF](<../../raw/Data structure/ปี67/Lecture 7 Hashing/Lecture 7 Hashing.pdf>) · **Wiki:** [[Lecture-7-Hashing|Lecture 7]] · **Pages/Text:** 20p / 4,497 chars

> **Page 1-2**
> **ROAD MAP - HASHING**
> - General Idea
> - Hash Function
> - Separate Chaining
> - Open Addressing
> - Rehashing
>
> **Page 3**
> **Hashing**
> - Hashing คือการนำข้อมูลมาเก็บใน Hash Table (ใน Python ใช้ datatype list).
> - **TableSize**: ขนาดของตารางที่แน่นอน.
> - **Key**: ส่วนประกอบของข้อมูลที่ใช้ในการค้นหา.
> - **Hash Function**: ทำหน้าที่แปลง Key เป็นตัวเลข (index ในอะเรย์) ในช่วง 0 ถึง TableSize-1.
> - **Ideal Case**: พยายามให้ทุก Key ที่ต่างกันไปลงใน index ที่ต่างกัน (แต่ในความเป็นจริงมักเกิดการชน).
> - **Complexity**: เป้าหมายคือต้องการให้ Insert, Delete และ Find ทำงานใน O(1) time.
>
> **Page 4**
> **An ideal hash table**
> - กระจายข้อมูลให้สม่ำเสมอที่สุด.
> - สิ่งที่ต้องพิจารณา:
>   1. เลือก Hash Function ที่ดี.
>   2. วิธีการจัดการเมื่อเกิดการชนกัน (Collision Resolution).
>   3. การตัดสินใจเรื่องขนาดของ Table.
>
> **Page 5**
> **Hash function (Integers)**
> - สูตรพื้นฐาน: `index = Key % TableSize`
> - ตัวอย่าง: TableSize = 10, Keys = 120, 330, 1000.
> - **ข้อแนะนำ**: TableSize ควรเป็นจำนวนเฉพาะ (Prime Number) เพื่อช่วยลดการชนของข้อมูล.
>
> **Page 6**
> **Hash function (Strings)**
> - นำค่า ASCII ของตัวอักษรมารวมกัน.
> ```python
> def hash(key, table_size):
>     hash_val = 0
>     for char in key:
>         hash_val += ord(char)
>     return hash_val % table_size
> ```
>
> **Page 7**
> **Collision (การชนกัน)**
> - เกิดขึ้นเมื่อข้อมูลใหม่ต้องการเก็บใน index ที่มีข้อมูลอื่นจองไว้แล้ว.
> - วิธีแก้ปัญหาหลัก:
>   1. **Separate Chaining**: ต่อข้อมูลที่ชนกันเป็นโซ่ (Linked List).
>   2. **Open Addressing**: หาช่องว่างอื่นในตาราง.
>
> **Page 8**
> **Separate Chaining Hash Table**
> - เก็บลิสต์ของทุกตัวที่แฮชไปที่ index เดียวกัน.
> - **ข้อควรระวัง**: ถ้า TableSize ไม่เป็นจำนวนเฉพาะ การกระจายจะไม่ดี.
>
> **Page 9**
> **Open Addressing**
> - เมื่อเกิดการชน จะพยายามหาช่องว่างอื่นตามลำดับ: `hi(X) = (hash(X) + F(i)) mod TableSize` โดยที่ F(0) = 0.
>
> **Page 10-11**
> **Linear Probing**
> - `F(i) = i`: ค้นหาช่องว่างถัดไปทีละ 1 (เช่น 0, 1, 2, ...).
> - **ปัญหา**: ลบข้อมูลออกยาก (ต้องทำเครื่องหมาย deleted) และเกิด **Primary Clustering** (การเกาะกลุ่มของข้อมูล).
>
> **Page 12-14**
> **Quadratic Probing**
> - `F(i) = i²`: ค้นหาช่องว่างแบบยกกำลังสอง (เช่น 1, 4, 9, ...).
> - ช่วยแก้ปัญหา Primary Clustering แต่ยังอาจเกิด **Secondary Clustering** ได้.
> - ตารางอาจไม่เต็ม แต่หาช่องว่างไม่เจอก็ได้.
>
> **Page 15-17**
> **Double Hashing**
> - ใช้ฟังก์ชันแฮชตัวที่สอง: `F(i) = i * hash2(X)`.
> - สูตร hash2 ที่ดี: `hash2(X) = R – (X mod R)` โดย R เป็นจำนวนเฉพาะที่มีค่าน้อยกว่า TableSize.
>
> **Page 18-20**
> **Rehashing**
> - เมื่อจำนวนข้อมูลในตารางมากเกินไป (Load Factor > 0.5 หรือ 0.7) การหาตำแหน่งใหม่จะใช้เวลานาน.
> - **วิธีแก้**: สร้างตารางใหม่ที่มีขนาดใหญ่ขึ้น (ประมาณ 2 เท่าและเป็นจำนวนเฉพาะ) แล้วย้ายข้อมูลทั้งหมดไปตารางใหม่.

> **Page 1-2: insert(14)**
> **Algorithm:**
> ```python
> def insert(self, x):
>     if self.is_full(): return
>     self.currentSize += 1
>     hole = self.currentSize
>     while hole > 1 and x < self.array[hole // 2]:
>         self.array[hole] = self.array[hole // 2]
>         hole //= 2
>     self.array[hole] = x
> ```
> - การทำงานจะไล่เช็คตั้งแต่ตำแหน่งรูที่ว่างอยู่ขึ้นไปหา parent (`hole // 2`).
> - ถ้า x มีค่าน้อยกว่า parent ให้เลื่อน parent ลงมา และขยับรูขึ้นไป.

> **Page 3-4: deleteMin()**
> **Algorithm:**
> ```python
> def delete_min(self):
>     if self.is_empty(): return
>     min_item = self.array[1]
>     self.array[1] = self.array[self.currentSize]
>     self.currentSize -= 1
>     self._percolate_down(1)
>     return min_item
> ```
> - การลบตัวที่น้อยที่สุด (Min) จะเอาตัวสุดท้ายมาไว้ที่ root แล้วทำ **Percolate Down** เพื่อปรับลำดับให้ถูกต้อง.
